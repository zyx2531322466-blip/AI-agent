# 第一次用，就这样走

不用先读文档。下面从**建项目**开始，一路走到"能给上级汇报"。

## 先花一分钟：命令怎么写

所有命令都是同一个形状：

```
pm-agent  <做什么>  [项目目录]  [其它参数]
```

- `pm-agent` 是程序本身。**在本仓库里**它在 `.\.venv\bin\pm-agent.exe`
  （Windows 上开头的 `.\` 是"当前目录下的"的意思，不能省）。
  正式安装过命令行入口的机器上，直接写 `pm-agent` 就行。
- 第二个位置一般是**项目目录**，不写就用当前目录。例：`pm-agent show ..\我的项目`
  **这条命令操作哪个项目，完全由你写的那个目录决定**——数据都在那个目录里，
  两个项目之间不会互相串。你建了自己的项目，就要在每条命令里点它的名，
  否则很容易一直在看示范项目、却以为自己的 `--goal` 没生效。
- 参数一律以 `--` 开头。
- **任何命令后面加 `--help`，它就列出自己的参数**——这是最可靠的一手说明：
  `pm-agent --help` 看全部命令，`pm-agent init --help` 看某一条的参数。
- 少数命令的第一个位置被别的东西占了（`track` 是那句话、`skill` 是能力单元的名字），
  这类命令的项目目录要用 `--path`（简写 `-C`）给，例如
  `pm-agent track "T003 做完了" --path ..\我的项目`。

### 我想做的事 → 敲哪条

| 我想做的事 | 敲什么 |
| --- | --- |

## 0. 建项目（1 分钟）

**想从自己的项目开始**：用 `init` 建一个空项目（只有骨架：元信息 + 空模板 +
数据目录，需求是 0 条；内容要 `specify` 或你自己写 `spec.md`）。

```
pm-agent init ..\我的项目 --name "我的项目" --goal "一句话说清这个项目要达成什么"
```

- `..\我的项目` 是**项目放在哪个目录**，程序会建它；目录已经存在也能用，
  已有的文件不会被覆盖。
- `--name` 项目名称、`--goal` 一句话目标 —— 这两个**必填**，少一个命令会直接
  报错并告诉你缺哪个。
- 想记下"这个项目我想学到什么"，再加 `--learning-goal "……"`，可以重复写多次
  （FR-051）。写下来的东西会出现在 `show` 和 `resume` 里。
- 不想要 git 版本库就加 `--no-git`。

**只想练手**：`demo` 建一个已经带数据的示范项目，不用自己想目标。

```
pm-agent demo ..\演示项目
```

目录里已经有东西时它会拒绝动手。`--reset` 是"先清空再重建"，听起来很顺手——
所以它被上了锁：**只认本工具建的示范项目**（那种目录里有一个 `.pm-agent-demo`
标记文件）。指到别的地方（你自己的项目、仓库、桌面）它会直接拒绝，一个字节都不动。
真实项目要重建，请自己删那个目录。

建完看一眼它长什么样：

```
pm-agent show ..\我的项目
```

## 1. 接上：`resume`（1 分钟）

```
pm-agent resume ..\演示项目
```

如果你建的是自己的空项目，这一步会说"还没有交接记录"——那是正常的，第一次都这样。
示范项目里有一份交接记录，所以能看到它本该给出的东西：**上次做了什么、上次留下的
结论、现在能动手的任务**。每次开新会话前，第一件事就该是它。

## 2. 看它怎么讲"为什么"（1 分钟）

```
pm-agent stage specify --explain
```

每个阶段都会说明目的、输入、产出，还有**依据**（对应哪几条需求）。
加 `--explain` 会再给出取舍和被放弃的备选。这条不需要项目目录。

## 3. 自己走一遍主链路（5 分钟）

下面几条要用到模型。先用 `pm-agent ask "在吗"` 确认接好了；没有密钥就加
`--provider echo`，至少能看出它跑到哪一步。
报 `CERTIFICATE_VERIFY_FAILED` 是证书问题（MSYS2 版 Python 上常见），把系统 CA 包
设给环境变量 `PM_AGENT_CA_BUNDLE` 就好，具体路径见 README 的「配置模型」。

```
pm-agent specify ..\演示项目          # 把目标整理成规范
pm-agent breakdown ..\演示项目        # 拆成带依赖与优先级的任务
pm-agent work --path ..\演示项目      # 让 AI 接手一条任务：自己读齐上下文、产出交付物、留成证据
pm-agent tasks ..\演示项目 --ready    # 现在能动手的是哪些
pm-agent track "T003 做完了，提交 abc123" --path ..\演示项目
pm-agent report ..\演示项目 --audience 上级
```

`work` 是最能看出这套东西价值的一步：它会自己挑一条**依赖已满足**的任务（也可以点名
`pm-agent work T003 --path …`），把这条任务的来源需求、相关决策、相关做法一起装进上下文，
然后产出**这条任务该交付的文件**，**直接写进项目目录**（代码就落在代码文件里），
同一条变更里再留一份记录说明"产出了哪些文件、依据什么"。写歪了就 `pm-agent undo` 一次全退回。
**它不改任务状态**——完成仍要你看过、跑过、再用 `track` 记证据（FR-014）。
同一条任务它**只肯做一次**：再跑会先告诉你上次产出了哪些文件，然后拒绝（想重来先 `undo`；
确实要叠加就加 `--redo`）。它还会在回显里点明"项目：<名称>"——`work` 和 `track` 的项目目录
是用 `--path` 给的，抄漏了会打到别的项目上。
写完之后它会**当场问你一句"这条任务算完成了吗"**：答 y 就记为完成、证据自动挂上；答 n 就停在
"进行中"，它把以后怎么标的命令递给你。（`--yes` 只跳过"要不要写"这一步，不会替你判完成；
想连这步都自动化就用 `--done`。）

注意最后两条写法不一样：`track` 的项目目录要用 `--path` 给，因为第一个位置留给
了那句话。**拿不准就加 `--help`。**

## 4. 看它会主动提醒什么（2 分钟）

```
pm-agent risks ..\演示项目
pm-agent tasks ..\演示项目 --coverage
```

风险分五类，每条都标着是**事实**还是**推测**；处置过的预警不会再重复打扰。

## 5. 试着让它复用一次做法（1 分钟）

```
pm-agent skills ..\演示项目 --suggest "帮我评审一下这份需求规范"
pm-agent skill requirement-review --why -C ..\演示项目
```

内置了四个能力单元：需求评审、风险复盘、周报汇总、完成前验证。拒绝一次，它两周内不会再提。

## 卡住了怎么办

- **不知道该敲什么** → 上面那张表；或者 `pm-agent --help`、
  `pm-agent <那条命令> --help`。
- **报"项目工作区有问题，无法打开"** → 十有八九是**没在项目目录里跑**：
  加上项目目录，或者用 `--path`。项目目录指的是有 `project.yaml` 的那一层。
- **报"没有名为 xx 的阶段"** → 阶段名只有这几个：specify / plan / tasks / track。

---

**走完之后**：示范项目整个删掉就行，它是独立的，删它不影响任何真实项目。

**哪一步卡住了？** 那多半不是你的问题，是这份引导还不够好——记下来。
